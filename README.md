Phase 5A.1でOnlineのDataset照合・読込件数診断と補給拠点/Armyマーカーを修正しました。実ファイル190地域 / 補給拠点72 / 初期軍59の検証と、元の0件症状の再現範囲は [Phase 5A.1修正報告](docs/PHASE5A_1_REPORT.md) を参照してください。Phase 5Bの変更は [Phase 5B報告](docs/PHASE5B_REPORT.md) を参照してください。

京都市の国勢統計区KMLを使った同時命令型ゲームと、ゲーム用地図設定を編集するWebアプリです。実装範囲は **Phase 7A「Render公開Web対応」まで**。仕様の正本は [spec.md](spec.md)（第33節）、最新の検証は [Phase 7A報告](docs/PHASE7A_REPORT.md)（6C単体は [Phase 6C報告](docs/PHASE6C_REPORT.md)） です。実際の試遊は **[PLAYTESTING.md](docs/PLAYTESTING.md)** を参照してください。以前の記録は [Phase 1](docs/PHASE1_REPORT.md)・[Phase 1.5](docs/PHASE1_5_REPORT.md)・[Phase 2A](docs/PHASE2A_REPORT.md)・[Phase 2B](docs/PHASE2B_REPORT.md)・[Phase 3A](docs/PHASE3A_REPORT.md)・[Phase 3B](docs/PHASE3B_REPORT.md)・[Phase 4A](docs/PHASE4A_REPORT.md)・[Phase 4B](docs/PHASE4B_REPORT.md)・[Phase 5C](docs/PHASE5C_REPORT.md)・[Phase 6A](docs/PHASE6A_REPORT.md) にあります。

都市部の採用範囲、補給拠点、初期配置は未確定なので、京都の初期設定は **全地域を未採用、補給拠点・初期配置なし** としています。画面には全227地域を表示します。御苑のゲーム用障害物境界案は初期設定に含みます。この初期設定はゲーム用の確定地図ではありません。地名は公式データの表記を保持します（例: 常磐野）。

## 1. 必要なソフト（Windows 11）

- [Node.js公式サイト](https://nodejs.org/) の **Node.js 24系**。package.jsonと.node-versionで24 majorへ固定しています。
- Microsoft Edge / ChromeなどのWebブラウザ。
- VS Codeは編集に便利ですが、利用には必須ではありません。

Windowsスタートメニューから「PowerShell」を開き、確認します。

```powershell
node --version
npm.cmd --version
```

`v24...` と npm の番号が出れば利用可能です。インストール直後に認識されなければPowerShellを一度閉じて開き直します。

この環境ではPowerShellが `npm.ps1` を禁止するため、全手順で **npm.cmd** を使います。通常の `npm install` や `npm run dev` と同じnpmを実行します。PowerShellの実行ポリシー変更は不要です。

## 2. 初回インストール

リポジトリのフォルダーに移動し、依存ライブラリを取得します。最初の1回はインターネットが必要です。

```powershell
Set-Location "C:\Users\zikke\Documents\kyoto-diplomacy"
npm.cmd ci --include=dev
```

今回の作業ではインストール済みです。別のPCや新しいコピーでは上のコマンドを実行してください。

## 3. 地図エディタを開く・閉じる

```powershell
npm.cmd run dev
```

PowerShellは開いたまま、ブラウザで **http://127.0.0.1:5173/** を開きます。トップ画面の「開発ツール」から「地図エディタ」を押します。初回は公式227地域の変換済みデータを表示します。

停止するときは起動したPowerShellで **Ctrl + C** を押します。`バッチ ジョブを終了しますか (Y/N)?` が出た場合は `Y` を入力してEnterを押します。再開は同じコマンドです。

このコマンドはWeb画面のみ起動します。オンラインは第16節の dev:online を使います。

## 4. KML原本と再インポート

原本の配置場所は次です。ファイルは加工せずに保存します。

```text
data/source/kyoto-2020-wgs84/
```

今回はSPEC準拠の **京都市公式Dataset 00670の国勢統計区KML 227件** を取得済みです。取得元のリソースURLは同フォルダーの `manifest.json` にあります。00631の旧データは使用していません。

自分で配置する場合は [京都市 Dataset 00670](https://data.city.kyoto.lg.jp/dataset/00670/) から **国勢統計区ごとのKML（WGS84）** をダウンロードし、このフォルダーへ置いてください。**行政区全体のKMLは混ぜないでください**。サブフォルダーも検索します。ダウンロード時刻が付いたファイル名にも対応します。

```powershell
npm.cmd run map:import
```

原本は変更されません。国勢統計区ID・番号・地名・行政区・原本ファイル名・SHA-256・Document名・Placemark識別情報を保持し、次を作成します。

- `data/generated/regions.json`: Webと検証で使う地域データ。
- `data/generated/regions.geojson`: 通常のGeoJSON FeatureCollection。
- `data/maps/kyoto-urban/initial-config.json`: 初期設定。すでに存在する場合は上書きしません。

再インポート後はブラウザを再読み込みします。ブラウザに保存した編集設定は復元されます。データにない参照を持つ設定は読み込めません。

公式データを再取得する補助コマンドもあります。原本がすでにあれば上書きせずにスキップします。公式サイトへのアクセスが必要です。

```powershell
npm.cmd run map:download
npm.cmd run map:import
```

新しいデータで置き換える場合、原本を別フォルダーへバックアップしてから配置してください。同じ地域のKMLを重複配置するとID重複エラーになります。

KMLがない状態で `map:import` を実行しても既存生成データを削除しません。生成データもない場合、Web画面は明記した **架空サンプル** で動作します。

## 5. 地図の編集

1. 左上「行政区」で対象を選びます。「選択区を拡大」で位置を確認できます。
2. 地図または左の一覧で地域をクリックします。地域名検索も使えます。
3. 右パネルの「この地域を採用」で使用・除外を切り替えます。「採用・除外を切替」モードならクリックだけで切り替えられます。
4. 「区を全採用」「区を全除外」は選択中の行政区にだけ適用します。全行政区表示では無効です。
5. 「補給拠点」、初期ユニット、初期ユニットの勢力を設定します。初期ユニットをONにしたときの勢力欄は地域の行政区を選択して表示するので、必要に応じて変更します。軍数は固定しません。旧ホーム勢力は「互換用 / 将来検討（homeWardId）」の中に保持しています。オンライン開始時の補給拠点初期所有者だけに使います。採用補給拠点の元行政区と一致すればその区の所有、未設定なら中立です。Buildや現在支配には使いません。
6. ドラッグで移動、ホイールまたは＋/−で拡大縮小、「全体に戻す」で表示をリセットできます。ホバーで地名を表示します。

編集モードでは色が付いた地域が採用、灰色が除外です。地図上の **明るい円は補給拠点、ピン型Armyは初期ユニット**、濃色の塗りと境界線は侵入不能障害物です。ピン色が所有勢力を表し、白い三角記号が陸軍の目印です。勢力名はhover・選択で確認できます。一覧の○・▲は設定済み項目の目印です。

左京区や右京区の山間部を自動で除外しません。地図を確認して人が採用範囲を決めます。除外しても補給拠点・初期配置・overrideの設定は保持されるので、残った不正設定は検証画面から修正してください。

## 6. 隣接関係

採用地域の共有境界を計算します。点接触だけでは隣接にしません。MultiPolygonと穴の境界も扱います。障害物を差し引いた形状を使い、隣接は双方向です。

右の「座標誤差の許容距離」と「共有境界の最小長」は変更できます。初期値の0.5m / 5mは **地理演算の調整用初期値** です。ゲームの採用範囲やバランスを決定する値ではありません。

1. 地域Aを選択します。
2. 「隣接override」モードにします。青枠が現在の最終隣接です。
3. 別の採用地域Bをクリックすると、隣接を追加または削除します。Aの選択は維持されます。
4. 隣接一覧の「削除」でも削除できます。「詳細を選択」に戻すと別地域を選べます。
5. 「手動override」を開くと差分を確認でき、「差分を取消」で自動生成値に戻せます。

設定には `adjacencyAdd` / `adjacencyRemove` の差分を保存します。自動隣接を再計算しても差分を適用します。除外地域・存在しない参照・矛盾した差分は検証エラーです。

重い計算はWeb Workerで実行します。「計算中」が消えるまで、隣接編集とMapDefinition出力は待機してください。

## 7. 障害物

京都御苑は中立地域ではなく、完全な侵入不能障害物です。通常regionや隣接グラフには登録しません。新規設定では [御苑のゲーム用境界案](data/maps/kyoto-urban/kyoto-gyoen-obstacle.geojson) を適用します。以前のブラウザ保存設定・JSONはそのまま復元します。Phase 2Aの境界へ更新するときは、編集モードで「御苑のゲーム用境界案を読み込む」を押してください。同じIDの御苑境界だけを置換し、他の障害物は残します。ユーザーが編集した境界を自動で上書きしません。

Phase 2Bでは、障害物ポリゴン全体を半透明の濃い緑で塗り、境界線と薄いハッチングを重ねます。表示形状はGeoJSONのポリゴンそのもので、差し引き後の地域と同じ境界を使います。標準の御苑案がない/異なる場合は注意を表示します。手動編集した境界でも注意は出ますが、現在の設定を保持します。

この案は[国土地理院の標準地図](https://maps.gsi.go.jp/development/ichiran.html)と[環境省の御苑案内図](https://www.env.go.jp/garden/kyotogyoen/2_guide/map.html)を参照した概略です。Phase 2Aでは上辺・左右辺の基本形を保ち、**下側2頂点を滋野の原形状の南端（緯度35.0173548653）まで延長**しました。実敷地を精密再現するものではなく、ユーザー指定の単純なゲーム用境界です。座標と出典はGeoJSONの中にあります。

現在の境界は京極・滋野・竹間・富有と重なり、滋野の差し引き後形状は2部分になります。元KMLは変更せず、滋野は同じ地域IDのMultiPolygonとして保持します。必要な通行可否は地図を確認して隣接overrideで調整してください。初期設定へ隣接差分は追加していません。

境界を直すときは、上京区を選び「選択区を拡大」→障害物欄の「境界を編集」→「頂点Nを移動」→地図上の移動先をクリックします。番号は地図にも表示します。「頂点を1つ戻す」で末尾を削除し、地図クリックで新しい点を追加できます。障害物名と「境界の出典・編集意図」を記録して「侵入不能境界を確定」を押し、設定JSONまたは障害物GeoJSONを保存してください。「作成を取消」では確定前の編集を取り消します。

新規作成は「地図上で侵入不能境界を作成」を押し、外周を囲む順に3点以上クリックして確定します。自己交差は拒否します。画面で頂点編集できるのは穴のない単一Polygonです。穴付きPolygon・MultiPolygonは次のGeoJSON読込で対応します。

右の「障害物GeoJSONを読込」でPolygon / MultiPolygonのFeatureCollectionを読み込みます。**既存レイヤーを置換**します。各Featureは以下の形です。座標はWGS84の `[経度, 緯度]`、外周・穴は始点と終点を閉じてください。`id` は一意、`name` と `source` は必須です。

```json
{
  "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "id": "obstacle-example",
    "properties": { "name": "障害物名", "source": "出典URLとライセンス等" },
    "geometry": {
      "type": "Polygon",
      "coordinates": [[[135.744,35.039],[135.746,35.039],[135.746,35.052],[135.744,35.052],[135.744,35.039]]]
    }
  }]
}
```

上記は **架空テスト形状で、京都御苑ではありません**。動作確認は、画面上部の「架空サンプルで確認」→「分断テスト用の障害物を追加」→「検証」で行えます。読込用ファイルは `data/maps/sample-obstacle.geojson` にあります。京都データへ自動適用されません。

地図の「障害物差し引き後」で表示を切り替えられます。検証は面積の重なり・差し引き後の複数部分・領域全消失を検出します。元ポリゴンは保持します。複数部分があるMapDefinitionの出力時には確認を表示し、同一論理地域のMultiPolygonとして出力します。論理地域の分割判断は自動で行いません。

## 8. 保存・読込・検証

画面上部の **「設定JSONを保存」** でダウンロードします。通常はWindowsの「ダウンロード」フォルダーに保存されます。必要ならエクスプローラーで `data/maps/kyoto-urban/` にコピーします。

**「設定JSONを読込」** から保存ファイルを選ぶと、採用状態、拠点、互換用ホーム、初期配置、表示位置override、隣接差分、許容値、障害物を復元します。Phase 1のJSONも引き続き読めます。不正な形式や存在しない地域の参照は読込エラーとなり、現在の設定を保持します。

編集内容はブラウザ内にも自動保存します。ただし別ブラウザ・別URLには引き継がれず、ブラウザデータを消すと失われます。**作業の区切りでJSONを保存してください**。京都と架空サンプルの保存設定は分かれています。

右の「検証」ではID重複、参照不正、非対称隣接、孤立、連結成分、除外地域への隣接・初期配置、override矛盾、初期ユニット重複、障害物交差・分断、表示位置の範囲外等を確認できます。地域別degree、行政区間の接続ペア、直接接する区数、区内の採用地域・拠点数、勢力別初期ユニット数も表示します。旧ホーム拠点の集計はレポートJSON内に互換用として保持します。バランスの採点は行いません。

エラーがあると **「MapDefinition出力」** は無効になります。編集用の設定JSONは保存できます。「検証レポートを保存」で客観値と問題一覧も保存できます。

MapDefinitionは元形状・差し引き後形状・表示アンカー・設定・最終隣接を持つ静的データです。現在所有者、実際のゲーム中ユニット、秘密命令、装備などは含みません。

CLIでも検証できます。最初は未採用の初期設定、保存した設定を使う場合はファイルパスを指定します。

```powershell
npm.cmd run map:validate
npm.cmd run map:validate -- "data/maps/kyoto-urban/kyoto-urban-config.json"
```

`data/generated/validation-report.json` を出力します。エラーなしの場合は `map-definition.json` も生成します。警告がある場合はレポートを確認してください。

## 11. 構成と実装範囲

初心者がリポジトリ直下からすべてのコマンドを実行できるよう、**npm packageは1つ**にしました。フォルダー単位で責務を分け、将来Node.jsサーバーから地図処理を利用できます。workspacesや追加のモノレポ管理ツールは使用しません。

```text
apps/web/                 React + Vite、SVGエディタ、オンラインUI、計算用Worker
packages/shared/         静的地図型、Zod runtime validation
packages/map-core/       地理演算、隣接、override、検証、自動テスト
packages/rules-core/     UI・通信に依存しない陸軍裁定、命令検証、同時撤退
apps/server/              Node.js + Socket.IO、認証した参加者別に状態を配信
packages/online-core/    区割当・正式初期化・ルーム・秘密提出・自動進行
packages/game-core/      年間状態、支配/SC更新、冬清算、公開イベント・装備・有効隣接
packages/map-tools/      KML取得・変換・設定検証CLI
data/source/             加工しない公式KML、取得元一覧
data/generated/          変換済み地図・検証結果（Web配信用）
data/maps/               設定JSON、架空障害物
data/config/             公開イベントの抽選重み、勝利設定・既定年数
tests/browser/           実ブラウザ操作テスト
docs/                    実装・検証記録
```

隣接は京都付近の緯度35°を基準にした局所投影でメートル換算し、近くの境界線分を空間セルで絞り、ほぼ平行な境界の重なり区間を統合して長さを測ります。地球規模の汎用測地用途を想定しません。地理演算はTurf、KML読込はfast-xml-parserを使用します。

Hold / Move / Support / Retreat裁定と年間進行、オンラインの秘密命令・自動裁定・復帰を維持しています。Phase 4AでHTTP起動確認と4種類の公開イベント、勢力装備、自転車2段階移動、バリケードを追加しました。Phase 4Bでは開始前検証、共通終了判定、同率順位と試遊ログを追加しました。締切・Discordは未実装です。**Phase 6Bで完成した機能を維持しています。** APIは [RULES_CORE.md](docs/RULES_CORE.md)・[GAME_CORE.md](docs/GAME_CORE.md)・[EVENTS_AND_EQUIPMENT.md](docs/EVENTS_AND_EQUIPMENT.md) にあります。

## 12. 表示位置（displayAnchor）

表示位置は障害物差し引き後の `playableGeometry` 内部へ自動配置します。凹型や穴を考慮し、境界から余裕のある点をpolylabelで計算します。MultiPolygonでは最大面積部分を優先し、同面積の場合も決定的に選びます。計算は地図生成時にWorkerで行い、描画のたびには計算しません。

手動修正は、採用地域を選択→「表示位置をこの地点に設定」→地域内部をクリック、で行います。範囲外・境界・障害物内は拒否し、設定を保持します。「表示位置を自動に戻す」でoverrideを解除します。保存する値は設定JSONの `displayAnchorOverride: [経度, 緯度]`、生成後の実際の位置はMapDefinitionの `displayAnchor` です。

ユニット・補給拠点はこの点を中心に表示します。画面全体の衝突回避による押し出しと長い指示線は廃止しました。近接する駒は重なることがあります。hover・選択で地域とマーカーを同時に強調して所属を確認します。

全体表示では勢力名を常時書かず、独自SVGのティアドロップ型Armyと円形補給拠点を表示します。ズーム倍率を `1000 / viewBox幅` とし、Armyの幅は `clamp(10, 22, 12 × 倍率^0.35)` px、ピンの高さは幅の18.75/14です。編集/Previewでは倍率4以上、hover、選択時に地域・勢力ラベルを表示します。プレイヤー盤面ではhoverまたは選択中の地点の地名を優先し、ズームだけで大量のラベルを出しません。命令入力中のhoverには命令・支援対象・移動先も表示します。補給拠点は軍の有無によらずArmy幅の6/14を半径とします。所有者は内側リングの色で示し、未所有は中立色です。同じdisplayAnchorを基準にし、所属地域から押し出しません。

## 13. ゲームプレビュー

「編集モード」は静的な採用範囲・補給拠点・初期配置等を変更します。「ゲームプレビュー」は **表示確認専用の現在状態** を変更します。ゲームの開始・占領・裁定・季節進行は行いません。

1. 編集モードで確認したい地域を採用し、必要なら補給拠点をONにします。
2. 画面上部の「ゲームプレビュー」を押して地域を選びます。
3. 「現在の支配勢力」を変えると地域色が変わります。同じ支配勢力なら通常地域も補給拠点地域も同じ色・同じopacityです。補給拠点は明るい円で識別し、中立/未支配は灰色です。区フィルターの強調もゲーム表示では現在の支配勢力を参照します。
4. 補給拠点地域では「補給拠点の現在所有勢力」を別に変更できます。補給拠点の内側リング色が所有勢力を表します。
5. 「プレビューユニットを配置」をONにし、「プレビューユニットの勢力」を選びます。Armyピンの色が所有者を表します。補給拠点は同じ中心の背後に円として表示します。
6. 支配を中京区、補給拠点所有を上京区、ユニットを左京区にするなど、3者が異なる場合を確認できます。
7. 「Preview JSONを保存」「Preview JSONを読込」で現在状態を往復できます。設定JSONとPreview JSONは別ファイルです。ブラウザ内にも別々に自動保存します。

「マップ設定からPreviewを再生成」は表示テスト用の初期状態へ戻します。採用地域の行政区を初期controllerとし、初期ユニット設定を読み取り、旧 `homeWardId` がある補給拠点のみ初期所有者へ変換します。中立補給拠点はnullです。homeWardIdを現在支配色やゲームルールには使いません。この初期化は実ゲームの開始処理・無所属区抽選とは別です。

Preview編集は静的設定を変更しません。設定の再計算でもPreviewで変更した支配と補給拠点所有を保持します。採用解除や領域全消失で無効になるPreview参照・ユニットは除外します。御苑そのものへは補給拠点・ユニットを設定できません。

## 14. ルールサンドボックス

1. 編集モードで地域を採用し、ゲームプレビューでユニットを配置します。編集モードの初期配置を使う場合は「マップ設定からPreviewを再生成」を押します。
2. 「ルールサンドボックス」を押します。現在のPreviewユニットをコピーし、そのコピーで裁定を試します。
3. 地図または「ユニット」で対象を選び、「命令種別」でHold / Move / Support Hold / Support Moveを選びます。移動先・支援対象は合法な候補のみ選べます。変更すると命令を登録します。最初に表示されるHoldを登録する場合は「この命令を確定」を押します。
4. 一覧と矢印で確認します。Moveは青実線、Supportは茶破線です。支援対象の実命令が合わない場合、支援は裁定時に失敗します。
5. 全軍に命令を入力して「裁定」を押します。未入力はエラーです。「未入力をHoldにする」は明示操作の補助で、正式ルールではありません。
6. ユニットの移動結果と、成功/失敗の理由・攻撃/防御/阻止の強さ・支援数・スタンドオフを確認します。
7. 排除された軍があれば撤退入力になります。対象軍を切り替え、合法な撤退先または解散を選びます。「この撤退入力を確定」で表示中の選択を登録できます。各軍の入力先は解決まで他の一覧・地図・矢印へ出ません。同じブラウザで各軍の視点を切り替えるローカル検証用です。撤退中は交渉禁止です。
8. 「撤退を同時解決」を押します。同じ撤退先を選んだ軍は全て解散し、撤退先がない軍も解散します。撤退先のある軍の未入力はエラーです。
9. 「次の命令を試す」で解決後のユニットから次の裁定を試せます。「初期Previewへリセット」で起動時のユニットへ戻せます。「ゲームプレビュー」で戻ると元のPreviewを確認できます。

Sandboxは**controller・補給拠点所有者・年・季節を更新しません**。ユニットの移動だけを反映するため、駒が移動先の地域色と異なるのは正常です。Sandboxでの結果は元のPreviewや設定JSONへ保存されません。ゲームプレビュー自体の編集・保存は引き続き可能です。

## 15. 年間進行（ローカル）

1. 地図の採用範囲・補給拠点・初期配置を設定し、Previewを再生成します。現在の支配・補給拠点所有・軍はPreviewで調整できます。初期地点は**静的設定のstartingUnit**から導出するため、Previewへ軍を追加しただけの地域はBuild地点になりません。
2. 「年間進行（ローカル）」を押します。参加勢力のチェックを確認します。初期選択は現在の軍の所有勢力です。未参加の行政区を脱落判定へ含めません。軍の所有勢力は全て参加指定が必要です。このローカル検証には無所属区抽選・正式初期化を適用しません。正式初期化はオンライン側の機能です。
3. 規定年数の初期値は5年です。必要なら試遊用に整数を指定し、「現在のPreviewから開始」を押します。公開イベントは初期ONで、seedを指定して再現できます（第17節）。表示は実暦ではなく「第1年」から数えます。地図・初期地点・Previewの状態をコピーして固定します。
4. 全軍のHold / Move / Support、装備取得後は自転車移動・設置を入力して「移動を裁定」。未入力はエラーです。「年間の未入力をHoldにする」は明示操作の補助です。Move成功で移動先のcontrollerが軍の勢力へ更新され、去った地域のcontrollerは維持されます。
5. 撤退があれば対象軍ごとに秘密入力して「年間撤退を同時解決」。撤退ではcontrollerを変更しません。解決後に「次へ進む」で補給拠点更新へ進みます。撤退がない場合も「次へ進む」で確認します。
6. 春または秋の補給拠点更新画面に、現在所有者→更新後のcontroller勢力を表示します。「次へ進む」で反映し、変更一覧を確認できます。補給拠点所有とcontrollerと軍の所有は別です。controllerがnullの補給拠点は所有もnullです。春更新後は秋の命令へ、秋更新後は冬へ進みます。
7. 補給拠点更新直後に参加勢力が補給拠点15か所以上かつ敵の初期補給拠点を2個以上所有していれば即終了・勝利表示になります。複数勢力が同時に該当する場合、最多補給拠点だけが勝利し、最多が同数なら同率勝者です。
8. 冬は勢力別の補給拠点数・軍数・増員可能数・必要解散数を確認します。補給拠点数が軍数を上回る差分が増員上限です。**その勢力の初期地点で、現在自勢力所有の補給拠点で、空いている地点だけ**を選べます。armyのみ作成します。増員枠を全て使う義務は設けていません。
9. 軍数が補給拠点数を超える場合、必要数だけ軍をチェックして解散します。自動選択はありません。不足・過剰なら「冬の増減員を確定」はエラーになり、冬に留まります。全勢力分の選択を一括確定します。
10. 冬清算後に「次へ進む」で脱落判定。補給拠点ゼロまたは支配する補給拠点以外の地域地域ゼロなら脱落し、その年の冬で終了し、最多補給拠点が勝利します。補給拠点同数は同率勝者・同順位で、12/12/10なら1/1/3位です。
11. 脱落がなく規定年数にも達していなければ、次年の春へ進みます。指定した規定年数の終了では最多補給拠点勢力を表示し、同数なら同率勝者を表示します。対局終了では共通の順位・試遊サマリーとログ保存を利用できます。
12. 「年間進行を初期状態へリセット」で起動時の盤面・年へ戻ります。編集/Preview/Sandboxへ切り替えて戻っても年間状態を保持します。データセットを切り替えると年間状態は終了します。

年間状態はメモリ内だけです。**再読み込み・タブを閉じると失われます**。今回ゲーム状態のExport/Importは追加していません。静的設定JSON・Preview JSON・MapDefinitionへ年間状態を混ぜず、ゲームの結果で元Previewも更新しません。ゲーム開始後に静的地図を編集しても、進行中のゲームは開始時の地図を使います。新しい地図を使うには再読み込み後にその地図で新しく開始してください。

## 16. オンライン対戦（Phase 5A）

地図エディタ・Preview・Sandbox・ローカル年間進行は引き続き利用できます。オンラインはサーバーが裁定・支配・補給拠点・年を管理する別モードです。

### 起動・停止

PowerShellで、必ず **package.jsonのあるリポジトリ直下へ移動してから** 実行します。

```powershell
Set-Location "C:\Users\zikke\Documents\kyoto-diplomacy"
npm.cmd run dev:online
```

`C:\Windows\System32` などでnpmを実行すると、そのフォルダーに **package.jsonがないためENOENT** になります。上のSet-Locationで移動すれば解消します。別の場所へコピーした場合は移動先を指定してください。

エクスプローラーからリポジトリ直下の **[START_ONLINE.cmd](START_ONLINE.cmd) をダブルクリック**しても起動できます。ファイル自身のある場所へ自動で移動します。Node/npmが見つからない場合や起動エラー時は、日本語の案内を表示して画面を残します。初回インストールは第2節で行ってください。

Phase 4Aでは、起動ログの文字列ではなく **画面のHTML応答とサーバーの`/health` HTTP 200の両方**を確認してから「HTTP確認成功・起動しました」を表示します。200ms間隔で約15秒待ちます。Viteのreadyログが先に出てもHTTP応答を待ち、HTTP確認後は旧起動タイマーで終了しません。失敗時には選択URL・ポート、子プロセスの実行状態・終了コード、最後のHTTP確認エラーを表示します。

標準候補はWeb **5173**、対戦サーバー **3001** です。未指定なら使用中のポートを飛ばし、各標準候補から+20まで順番に空きを探します。成功時に表示される **ONLINE GAME URL** をブラウザで開いてください。例えば5173が使用中なら5174になるので、以前のURLと取り違えないようにします。PowerShellは開いたままにし、停止はその画面で **Ctrl + C**。両方を停止します。`バッチ ジョブを終了しますか (Y/N)?` が出た場合は `Y` とEnterです。

ポート使用中の対処は次の順で確認してください。

1. 以前の `npm.cmd run dev` を起動したPowerShellを探し、不要なら自分でCtrl + Cを押します。
2. 既存サーバーを使い続ける場合、ポート未指定の `dev:online` は別の空きポートで共存できます。プログラムは既存プロセスを停止しません。
3. 手動で指定する場合は次を実行します。**明示したポートが使用中なら変更せず終了**し、対処を表示します。

```powershell
$env:WEB_PORT='5180'
$env:ONLINE_PORT='3011'
npm.cmd run dev:online
```

終了後、自動選択に戻すには次を実行します（PowerShellの環境変数はその画面に残ります）。

```powershell
Remove-Item Env:WEB_PORT -ErrorAction SilentlyContinue
Remove-Item Env:ONLINE_PORT -ErrorAction SilentlyContinue
```

使用状況を確認するコマンドです。ポート番号は調べたい番号へ置き換えられます。結果が空なら、そのポートに待受中のプロセスはありません。

```powershell
Get-NetTCPConnection -LocalPort 5173 -State Listen
Get-Process -Id (Get-NetTCPConnection -LocalPort 5173 -State Listen).OwningProcess
```

開発Webを5173、標準proxyのまま起動している場合は、別PowerShellで `npm.cmd run dev:server` を起動しても利用できます。空きポートの自動選択は一括起動の `dev:online` の機能です。ポート選択が変わるとブラウザ保存設定・復帰情報は別URL扱いになるため、地図設定JSONを保存して新しいURLで読み込んでください。

### 3人で試す（同じPC）

1. 地図エディタで全11区に採用地域・補給拠点・初期軍を設定し、「設定JSONを保存」でMapConfigを保存します。3人でも11区すべてが抽選候補です。初期軍は採用・侵入可能な補給拠点へ置きます。初期補給拠点所有は「互換用 / 将来検討（homeWardId）」で元行政区を指定します。未設定なら中立です。3人目標補給拠点23か所を満たす総数が必要です。未採用の京都初期設定では開始できません。
2. 「オンライン対戦」でnicknameと任意の希望1区を入力し「ルームを作成」。Hostがロビーの「京都シナリオJSONを読み込む」で保存ファイルを選び、読込済み表示とError / Warningを確認します。短い6文字のコードを参加者へ伝えます。
3. ブラウザの**新しいタブ**を2枚開いて同じURLへアクセスします。各タブで「オンライン対戦」、別nickname、ルームコードを入力し「ルームへ参加」。Edge/Chromeや別プロフィールでも利用できます。タブの「複製」は復帰情報がコピーされることがあるので避けてください。
4. 2人以下は「3人以上必要」と表示されます。全員接続中の3～11人で、PreflightのErrorが0ならHostが開始します。Warning詳細は確認してください。規定年数の初期値は5年で、開始前の変更は可能です。12人目と開始後の新規参加はできません。開始前なら退出・希望変更ができます。
5. 希望が単独なら優先、競合はseed付き抽選、残りはランダム割当です。希望は保証されません。他人の希望は公開しません。未割当の11−人数区は無所属として残り、地域支配・補給拠点は中立、初期軍はありません。
6. 勝利目標は開始時人数で **15 + (11−人数)** を計算し固定します。3人補給拠点23か所、4人補給拠点22か所、…、11人補給拠点15か所です。切断・脱落で変えません。

### 命令・提出状況・年間進行

- 地図上の自軍をクリックし、下部の「待機」「移動」「支援」、装備取得後は「自転車」「バリケード」を選びます。合法対象を地図で選んで登録します（第19節）。支援対象には他勢力の軍も選べます。矢印と本人の一覧は自分の入力だけです。軍がない生存プレイヤーも空命令書を確定します。
- 「未入力N軍はHoldになります」を確認して「命令書を確定」。サーバーが自軍の不足だけHold補完します。不正命令は拒否します。自分には補完済み提出内容、他人には「確定済み」だけが見えます。
- 提出状況は常に表示され、入力中・確定済み・不要・切断・脱落が分かります。全requiredが確定した瞬間に自動裁定します。ホストの裁定ボタンはありません。最後の確定前なら「確定解除」して編集できます。
- 撤退は排除された自軍だけ秘密入力します。候補または解散を選び「撤退命令書を確定」。撤退中は交渉禁止です。他人の撤退先は解決まで表示しません。候補のない軍は解散します。
- 春秋の移動・撤退後は自動で補給拠点更新し、次フェイズへ進みます。直前の公開裁定結果でMove・支援・スタンドオフ・排除・撤退と補給拠点変更を確認できます。次フェイズの新しい秘密入力とは分離します。
- 冬の必要解散または合法な空き初期地点補給拠点へのBuildがある人だけ提出します。Buildを0軍にする場合も「冬調整を確定」が必要です。必要解散数は手動選択してください。何も調整できない人は不要です。全員確定で一括適用し、冬後の脱落/年末判定、次年または終了へ自動進行します。
- 地域hoverで地名と元行政区名をカーソル付近に表示します。ピンや補給拠点の上でも同じ地域を確認できます。選択は細いアクセント枠と少し明るい塗りです。タッチ操作では選択地域の詳細欄を使います。

### 再接続と制限

同じタブを再読み込みするとオンラインへ戻り、サーバー発行のplayerId/tokenで復帰します。本人の下書き・確定済み入力も復元します。参加資格はタブごとのsessionStorageに保存するため、**タブを閉じると通常は復帰情報を失います**。一時切断は自動再接続します。他人へtokenは送信しません。同じ資格で再接続すると操作資格を新接続へ移します。

切断した確定済み提出は保持します。未確定の切断者は待ちます。強制Hold・skip・AFK/ターンtimerはありません。開始前のホスト切断は接続中の参加者へ移譲します。サーバーを停止/再起動すると部屋・盤面・下書きは全て失われます。その場合は「保存した参加情報を消す」から作り直してください。ゲーム中の設定編集は開始時に固定した地図へ影響しません。

観戦・チャット・DB保存・アカウント登録・Discord Activityは未実装です。規定年数は試遊用の仮設定5年。春秋の目標到達、冬の新規脱落、その後の規定年数という優先順で終了し、最多補給拠点勝利・同数は同率勝者です。京都の採用範囲や補給拠点/初期軍数の確定は引き続き人が行います。

### 同じLANの別PCから参加

ホストPCで、WebをLANへ公開する起動指定をします。対戦サーバーはローカル接続のままで、選択されたポートへWebからproxy経由で利用します。

```powershell
$env:WEB_HOST = '0.0.0.0'
npm.cmd run dev:online
```

ホストPCで `ipconfig` を実行して使用中ネットワークのIPv4アドレスを確認します。参加者は同じ信頼できるLAN内で **http://ホストPCのIPv4アドレス:実際のWebポート/** を開き、ルームコードで参加します。ポートは起動ログに出た番号です（5173とは限りません）。Windowsのネットワーク許可が必要な場合はプライベートネットワーク側を確認してください。LAN開発でルーターのポート開放は不要です。インターネット版は第26節のRender公開手順を利用します。ローカル限定へ戻すには停止後、`Remove-Item Env:WEB_HOST` を実行します。

通信・API・秘密情報の分離は [ONLINE_CORE.md](docs/ONLINE_CORE.md)、今回の検証結果は [Phase 5A報告](docs/PHASE5A_REPORT.md) を参照してください。**今回の実装はPhase 7Aで停止します。実Render公開は利用者のアカウント操作で行い、Discord Activity・永続DB・新ルールへ進みません。**

## 17. 公開イベント・装備を試す

第1年から、春・秋の命令入力前に全員へ公開イベントが出ます。冬には新規生成しません。開始時3～5人なら1件、6～8人なら2件、9～11人なら3件で、同じ種類は同じ季節に重複しません。候補が不足すれば生成できる件数だけで続行します。

| 種類 | 効果と期間 |
| --- | --- |
| 自転車 | 空いている補給拠点以外の地域に装備を配置。取得後は勢力所持の永続装備 |
| バリケード | 空いている補給拠点以外の地域に装備を配置。設置成功で消費し、次の移動季節から4季節、1辺を封鎖 |
| 道路工事 | 今季の移動・支援・撤退・自転車で1辺を通れない。撤退解決後に解除 |
| 臨時バス | 通常地図で距離2または3の非隣接地域を今季だけ接続。移動・支援・撤退・自転車で利用可 |

装備は移動と全撤退の後、補給拠点更新より前に、装備の地域を占有する軍の**所有勢力**が取得します。撤退での到着でも取得できます。空き地域に残った装備は自然消滅しません。所持する装備は、その勢力のどの軍でも使えます。装備IDを同じ季節に複数軍へ割り当てることはできません。バリケード装備はゲーム全体で1個だけで、地面に残っているか、誰かが所持している間は新しく出現しません。設置済みの封鎖は消費後の持続効果なので、次の装備の出現を妨げません。

**Bicycle Move**は1勢力1移動季節に1軍までです。装備・経由地域・第2区間の移動先を選びます。第1区間を通常軍と同時に裁定し、成功した自転車軍の第2区間を同時に裁定します。攻撃力は1で支援を受けません。第1区間失敗なら元の地域、第2区間失敗なら経由地域に留まります。曲がる経路も使えます。成功・失敗だけでは自転車を消費しません。

**Deploy Barricade**も1勢力1移動季節に1軍までです。通常の恒久隣接辺を選び、その軍は保持として防御します。保持支援を受けられます。排除されなければ設置成功し、次の春・秋Ordersから残り4→3→2→1季節と数えます。毎回の撤退まで封鎖し、4回目の撤退後に解除します。バスだけの辺や、持続中の封鎖と合わせて地図を分断する辺は選べません。

利用軍が排除されても、撤退に成功すれば予約した装備は次季節に使用可能です。撤退不能・競合・任意解散で利用軍が最終的に破壊されると、予約していた装備も消えます。利用していない所持装備は他の軍の破壊では失いません。

公開パネルにはイベント、マップ上の装備、勢力別所持数、封鎖辺と残り季節を表示します。画面上では装備の四角い記号、工事の短い橙線、バスの青緑破線、封鎖の赤線と残数を確認できます。装備命令の経路・対象辺・予約は本人だけに表示し、裁定後に結果を公開します。装備命令を入力した軍には自動Holdを追加しません。

一人で試す場合は第15節の年間進行を使います。開始前の「公開イベントを有効にする（検証用）」は初期ONです。「イベントseed」を同じ値にすると、同じ地図・盤面・操作で同じイベントを再現できます。1～2勢力のローカル検証では1件を要求します。通常ルールだけを確認するときはイベントをOFFにできます。オンラインにはこのOFF操作はありません。

抽選重みは [data/config/event-settings.json](data/config/event-settings.json) に同率の1で保存しています。変更後は開発サーバーを再起動し、新しいゲームを開始します。本番ビルドは再ビルドが必要です。ゲーム開始時の設定・seed・乱数counterはゲーム状態に保持されます。詳細は [EVENTS_AND_EQUIPMENT.md](docs/EVENTS_AND_EQUIPMENT.md) を参照してください。


## 18. 保存シナリオ・開始前検証・試遊ログ

地図エディタの「設定JSONを保存」で出力したMapConfigを、Hostが開始前ロビーの「京都シナリオJSONを読み込む」で選びます。サーバーが元Datasetからcompileし、シナリオ名・ハッシュ・採用地域数・補給拠点数・軍数を公開します。開始後は変更できません。

3人でも全11区の採用地域・初期軍・初期所有補給拠点が必要です。初期軍は侵入可能な補給拠点へ置きます。現在人数の目標（3人補給拠点23か所等）が補給拠点総数を超える設定も開始できません。開始ボタン近くのError / Warning件数と詳細を確認し、Errorは修正して読み込み直します。差・分断・低隣接数などWarningだけなら開始可能で、バランスを自動評価しません。

初回試遊の具体的な操作とChatGPTへ送る資料は [PLAYTESTING.md](docs/PLAYTESTING.md) を参照してください。正式な採用範囲・補給拠点・初期配置は人が決め、未採用の初期設定と原本KMLを保持しています。

## 19. プレイヤー向け画面・招待・地図操作

起動後はトップ画面です。「オンライン対戦」「ローカルで試す」「設定」が主ボタンです。地図エディタ・Game Preview・Rules Sandboxは下の「開発ツール」にあります。従来の保存/読込・隣接override・御苑編集・Sandbox・年間進行は利用できます。開発時に直接エディタへ入るURLは `/?tool=editor` です。この開発導線からオンラインへ入ると、検証用の従来フォームも表示します。

1. オンライン対戦→ニックネーム→ルームを作成。Hostが保存済みMapConfigを読み込みます。
2. ロビー上部の大きなルームコードを「コードをコピー」でコピーできます。「招待リンクをコピー」は現在開いているURLのoriginを使った `/?room=ABC123` を作ります。リンクを開くとオンライン参加画面へ進み、コードを入力済みにし、ニックネーム欄へ誘導します。
3. カードにHost・人数・接続範囲・シナリオ名・ファイル名・短縮ハッシュ・採用/補給拠点/軍数・規定年数・勝利目標を表示します。Hostの規定年数変更は他参加者のカードにも反映します。ErrorとWarningの詳細は開始前に確認します。
4. 開始後の上部バーで年/季節/フェイズ・自分の担当区・補給拠点/目標・軍数・確定状態を確認します。小さなルームコードは押すとコピーできます。左は公開イベントと折りたたみ結果、右は提出状況・補給拠点数・自分の装備です。「イベント・結果」「参加者・装備」でHUDを閉じると地図を広くできます。
5. 自軍のピンをクリックすると下部の操作が出ます。「待機」はその場で登録。「移動」は合法な移動先を地図で選びます。「支援」は対象軍を指定し、現在地を守る/移動を支援するを選びます。移動支援ならさらに移動先を指定します。他勢力の軍への支援も既存ルールどおり可能です。
6. 自転車は地図で経由地→終点を指定します。バリケードは自軍の地域との辺を封鎖する相手地域を指定します。装備が複数ある場合だけ使用する装備を選びます。合法候補はオンラインではサーバーが生成し、登録時にも検証します。「キャンセル」「命令を変更」で選び直せます。
7. 入力済み/全軍数と未入力Holdの案内を確認し「命令書を確定」。全員の確定前なら解除できます。誰待ちかは右の提出状況で確認します。撤退と冬は本人だけの専用入力を利用します。撤退中は交渉禁止です。

「ローカルで試す」は同じPCで全勢力を操作する試行モードです。用意した地図/Previewの軍をクリックして同じ下部操作を使えます。既存の段階ごとの裁定・補給拠点確認・冬操作を維持し、オンラインの自動Holdをローカルのルールへ追加しません。「年間の未入力をHoldにする」は明示的な補助操作です。トップへ戻っても同じタブなら盤面・命令・ログを保持しますが、再読み込みやタブ終了では失われます。

### 接続範囲

| 表示 | 意味 |
| --- | --- |
| LOCAL / このPCのみ | 127.0.0.1・localhost。招待先も同じPCで開きます |
| LAN / 同一LAN | 192.168.x.x、10.x.x.x、172.16～31.x.x等。第16節のLAN起動が必要です |
| NETWORK | その他の接続先。HTTPSだけでPUBLICと断定しません |

LANへ招待するときは、Host自身も `http://ホストPCのLAN IP:実際のポート/` を開いてコピーしてください。127.0.0.1を開いたままコピーするとLOCALリンクになります。HTTPのLANでClipboard APIが利用できない場合はブラウザの選択コピーを試し、それも不可なら表示されたコード/リンクを手動コピーできます。LOCALリンクでは「このURLは同じPCからのみ利用できます」と表示します。今回インターネット公開はしていません。PUBLIC hosting・Discord Activityは将来の別作業です。

## 20. Phase 5BのAudio

7種類の仮SEを同梱しています。BGMは未配置です。自作または利用できるBGMを次の名前で配置すると利用できます。SEの差し替えは第24節を参照してください。

apps/web/public/audio/bgm/domestic.mp3

7種類の任意SEのパス・長さの目安は [sfx-manifest.ts](apps/web/src/audio/sfx-manifest.ts) に集約しました。音源の配置手順は [効果音README](apps/web/public/audio/sfx/README.md) を参照してください。BGMの既存運用と音量設定を維持し、音源がなくても通常どおり遊べます。Phase 6Bで停止します。


## 24. Phase 6Bの作戦盤と仮SE

補給拠点選択は細い青緑リング、キーボードfocusは破線リングで示します。黒い既定focus枠を廃止し、補給拠点・Army・地名を隠しません。プレイヤー盤面では操作中の地名を優先し、ズーム時の大量ラベルを抑えています。必要な所属・所有情報はhover・地域インスペクタ・トレイから確認できます。

紙色の盤面と、山・森・等高線による外周の自然背景を追加しました。全プレイ可能ポリゴンと既知の障害物を背景のマスクから除外しています。御苑は既存の障害物表示を保ちます。自然背景は装飾で、通行可否やKML・MapConfigを変更しません。実際の標高・植生の再現ではありません。

初期表示は全補給拠点・初期軍のアンカー、また「全体に戻す」は全補給拠点と現在の軍を中心に、画面の縦横比でfitします。大きな無人外周ポリゴンに引っ張られず、都市部を大きく見せます。「全域を表示」は採用ポリゴン全体を表示します。パン・ズーム・行政区拡大・イベントfocusを併用できます。

7種類の短い効果音をローカル生成し、`apps/web/public/audio/sfx/*.wav` に同梱しています。「音量・設定」→「効果音を試す」で聞けます。選択、命令受理、移動演出、支援成功、補給拠点増加、スタンドオフ、本人の勝利に既存フックから再生します。BGM/SEの設定は独立し、SE OFF・音量0・ファイル不在でも遊べます。

再生成する場合は `npm.cmd run audio:generate`。生成スクリプトは7つの仮WAVを上書きするので、差し替えた音源は別名で保存し、sfx-manifest.tsのsrcを変更してください。Web用srcは `/audio/sfx/...`、配置先はpublicです。distはbuildで再生成されます。

Phase 6Bの背景・色・音源を維持しています。今回の公開Web対応は第26節を参照してください。



## 25. Phase 6Cの盤面と勝利条件

プレイヤー画面の呼び方を「補給拠点」に統一しました。全域表示付近では、中立・未所有の補給拠点だけ小さくなり、透明なクリック領域は維持します。Armyや所有済み拠点のサイズは変わりません。

## 26. Phase 7A — Renderで友達へURLを共有する

公開用コード・render.yaml・本番接続テストを用意しました。**GitHubへのpushとRenderでのDeployは未実施で、実公開URLはまだありません。** 初めて公開する場合は [DEPLOY_RENDER.md](docs/DEPLOY_RENDER.md) の順に、GitHubへpush → Renderログイン → Blueprint作成 → 環境変数 → Deploy → 公開URL確認を行ってください。

FrontendはRender Static Site / Free、BackendはRender Web Service / Free、RealtimeはSocket.IOのHTTPS/WSSです。npm workspaceはなく、root package一つのままです。Backend buildは `npm ci --include=dev && npm run build:server`、startは `npm run start:server`。build:serverは型確認、startは固定lockのtsxによる既存TypeScript entry実行です。Frontend buildは `npm ci --include=dev && npm run build`、公開先 `dist`。Nodeは24 majorです。

Backendに `NODE_ENV=production` と `FRONTEND_ORIGIN=https://実Frontendのホスト`、Frontendに `VITE_PUBLIC_DEPLOYMENT=true` と `VITE_ONLINE_SERVER_URL=https://実Backendのホスト` を設定します。PORTはRenderが供給し、0.0.0.0でlisten、healthは `/health`。VITE変数変更後はFrontendを再buildします。公開originだけCORS/WS handshakeを許可し、開発debug endpointを本番へ登録しません。秘密値をVITE変数へ入れません。

公開画面は「公開サーバー」と表示し、招待URLはアクセス中の公開Frontend URLを使います。Backendが休止している場合もFrontendは開き、「サーバーを起動しています。初回はしばらくかかることがあります。」と案内します。指数backoffで約90秒待ち、未接続なら「接続を再試行」。接続後にhealthへ定期アクセスはしません。

**Backendの再起動・再deploy・休止・保守により、進行中のRoom/Gameは失われる可能性があります。** メモリ保持でDBはありません。reconnect tokenは同じプロセスの本人復帰用で、対局の永続保存ではありません。数か月後は公開URLから新しい対局を開始できますが、進行途中の数か月保存は対象外です。

両サービスは `autoDeployTrigger: off`、branch mainです。公開後、DashboardのService Auto-Deploy OFFに加え、**Blueprint Settings → Auto Sync → No**も確認してください。通常のpushで更新せず、公開したいcommitだけManual Deploy。構成変更はManual Syncを使います。Backend更新は対局のない時間に行います。[公式Blueprint説明](https://render.com/docs/infrastructure-as-code#disabling-automatic-sync)

追加検証は `npm.cmd run test:production`。公開設定で別のdist-publicへbuildし、2つのローカルHTTPS originと実production entryでWSS・3人対局・招待・Move/Support・裁定・再接続・Audioパス・起動待ちを検証します。通常の6コマンドも引き続き使用します。自己署名のテスト用証明書を本番へ設置しません。実RenderのFree休止、別回線、実公開URLはDeploy後に人が確認します。

利用者側の作業: GitHub repository/main push、RenderのGitHub連携/Blueprint作成、実URLの環境変数設定とDeploy、Auto-Deploy/Auto Sync停止、3端末/別回線での公開確認、承認したシナリオJSONの読込。標準京都設定は採用0のままです。実装・検証と制約は [PHASE7A_REPORT.md](docs/PHASE7A_REPORT.md) を参照してください。Phase 7Aで停止し、Discord Activity・永続DB・新ルールには進みません。
