# Phase 5B 完了報告

実施日: 2026-10-03。仕様正本は `spec.md` 第28節です。実装前に `PHASE5B_DECISIONS.md` を全文反映し、以前のAudio専用案も今回の決定に合わせて統合しました。Phase 5Bで停止します。

## 1. 試遊で確認された問題への対応

決定資料の3人試遊では上京区・中京区・西京区がSC/Army 6/6・6/6・5/5で開始し、春437.5秒、秋183.7秒、支援0件でした。これを受け、イベント位置の発見、自軍の見分け、移動登録、対象軍から始める支援、同時裁定の視覚表示を実装しました。所要時間や支援利用が改善したかの人による再試遊はまだ行っていません。

回帰検証にはPhase 5A.1の実京都MapConfigを使用しました。190採用地域・72SC・59初期軍をサーバーがDataset 00670から再構成し、3独立ブラウザの担当区26102・26104・26111で自軍6・6・5軍を確認しています。検証用配置は本番初期設定に適用していません。

## 2. イベント位置の表示

`EventsPanel.tsx` で地域IDを地図の地域名・行政区名へ変換し、効果を併記しました。道路工事・臨時バス・地面の自転車/バリケード・設置済みバリケードが対象です。設置済み障害物の期限も表示します。

カードhoverは該当地域・辺を強調し、「地図で見る」は `MapCanvas.tsx` のcamera stateへfocus requestを送り、両端を含むpan/zoomと約1.6秒のpulseを行います。道路工事には橙色の×印を併記しました。イベント発生重み・抽選・期限は変更していません。

## 3. 右クリック移動

通常の命令選択状態で自軍を左クリック後、合法な地域の右クリックで既存Move命令を登録します。オンラインではサーバーの合法命令をそのまま使用し、サーバーが登録時にも検証します。contextmenuを抑止し、不正対象は命令を変更せず短い説明を出します。

支援・自転車・バリケードの操作中、未選択・確定済み・別フェイズ・裁定表示中には通常の右クリック移動を登録しません。タッチ用の「移動」からの左クリック操作も維持しました。

## 4. 自軍表示

担当区が分かるオンライン画面ではHUDに「あなた: 区名」と勢力色を表示し、自軍Armyだけに細い明るい縁取りを付けました。hoverには「自軍」または勢力名と地域を表示します。ローカルの全勢力操作には一つの担当区を仮定しません。ピン先端とSCのdisplayAnchorは維持しました。

## 5. 次の一歩の参考

選択した軍の一次移動候補へhoverすると、現在の `effectiveAdjacency` による二次候補を別の点線で示します。表示文言は「次の一歩の参考（現在の通行条件基準）」です。次季節のイベント・通行条件・占有を予測するものではありません。

自転車の第2移動先にも同じ視覚表現を使います。その操作では参考隣接ではなく、サーバー/既存装備処理が返す実際の合法な第2移動先を使用します。

## 6. 支援操作

`BottomActionBar.tsx` の通常プレイヤー操作を「支援する自軍→対象軍→現在地を守る/移動を支援する→移動先」に変更しました。対象軍の合法Moveと支援到達範囲の積集合のみを移動支援候補にします。現在地支援には既存の合法SupportHoldを使用します。

対象が自軍で本人のMove下書きがある場合のみ、その移動先の推薦ボタンを出します。他軍については公開位置と合法候補を使い、他軍の秘密命令を読みません。自然な日本語の要約、支援線、Escape・キャンセルを追加しました。SupportHold/SupportMoveの裁定ルールは維持しています。

## 7. 裁定演出

game-coreが裁定前後の軍位置、裁定後に公開可能な命令、成功/失敗、支援、スタンドオフ、排除をsnapshotに保存します。オンライン公開snapshotの装備命令からequipmentIdを除き、装備の秘密情報を保持しました。

`AdjudicationPresentation.tsx` と地図の演出レイヤーは、矢印0～0.4秒、同時移動0.4～2.0秒、衝突表示2.0～2.6秒、確定位置表示2.6～3.4秒、その後結果サマリーの順で表示します。時間は `data/config/presentation-settings.json` に保存しました。成功Moveは移動先へ、失敗Moveは距離40%まで進んで戻ります。自転車は実際の第1/第2裁定結果に従います。支援は破線・pulse、スタンドオフは点滅、排除は短い揺れで示します。

演出は確定済み結果を表示するだけで、サーバーの結果・自動フェイズ進行を変更しません。演出とサマリー中はクライアントの命令入力を停止します。「スキップ」で確定結果へ進み、「結果を閉じる」で次の入力へ戻ります。OSのreduced motionでは位置移動を減らし、結果表示を維持します。再接続・再読込は現在の確定盤面を表示し、古い演出を再生しません。

通常プレイヤー画面とローカル試行が対象です。開発ツールから入る従来の詳細画面は即時結果表示を維持しています。

## 8. Audio統合

自分で用意した音源の配置先は次です。音源は追加していません。

```text
apps/web/public/audio/bgm/domestic.mp3
apps/web/public/audio/bgm/adjudication.mp3
apps/web/public/audio/sfx/march.mp3
```

通常の命令・撤退・冬にはdomestic、裁定演出と結果サマリーにはadjudicationを指定し、約0.9秒でcrossfadeします。Audioインスタンスを音源ごとに再利用し、季節変更でdomesticを再起動せず、裁定後も再生位置を保持します。

`audio/sfx-manager.ts` は軍ごとに再生せず、移動段階で一つのmarchを鳴らします。移動終了・スキップ・画面離脱で停止します。設定画面に効果音ON/OFF・音量を追加し、BGMと独立にlocalStorageへ保存します。404・再生拒否・保存値破損でもゲーム操作を続行できます。タイトル・ロビー・終了の旧BGM枠は空欄を維持しました。

## 9. 中立SC

SCの所有表示には `supplyCenterOwnerWardId` だけを使います。nullは白地・暗色の境界で、内側の所有者リングを表示しません。controllerの色から所有者色を推測しません。hoverでも中立所有を確認できます。

Phase 5A.1の軍の有無で変わらないSC寸法、外周半径6・stroke1.6、内周半径3.8・stroke2、Army先端anchorは維持しています。軍とSCを地域外へ押し出していません。

## 10. 即勝利条件

正式な開始時、参加/無所属区の処理後に全SCの初期所有者を `initialSupplyOwners` へ保存します。春秋SC更新後の即勝利には、従来の人数別SC目標と、別の参加勢力の初期SCを現在2個以上所有する条件の両方が必要です。同じ相手の2SCも数えます。

初期中立・無所属区・自分の初期SCを除外し、初期所有者snapshotから毎回判定します。中央設定 `requiredRivalInitialSupplyCentersForInstantWin: 2` は開始時に固定し、HUDとログへ進捗を出します。複数の即勝利達成者がいる場合は達成者の中の最多SCが勝利します。規定年数・脱落による冬終了ではこの追加条件を使わず、従来のSC順位・同率勝者を維持します。

## 11. 試遊ログ

集計にSupportHold/SupportMove数、各勢力の敵初期SC・初期中立SCの現在所有数、裁定スキップ数を追加しました。スキップは認証済み参加者の現在の公開裁定だけを受け付け、同じ参加者・裁定の重複を除外します。マウス座標・下書き変更履歴・復帰tokenを記録しません。任意項目だった右クリック操作数の集計は追加していません。

ログversionは1を維持し、新しい集計欄には既定値を付けて以前のログを読めるようにしています。敵初期SC・初期中立SCの集計は各盤面snapshotでの現在所有数です。終了サマリーにも支援数とスキップ数を表示します。
