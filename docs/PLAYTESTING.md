# Phase 7G 試遊手順（Windows / 標準シナリオ・公開Web）

## Phase 7Gで確認する操作

1. 3人以上で開始し、別々の空き地域へのMoveと、同じ地域への競合Move・Supportを入力します。全員確定するまでは自分以外の命令は見えません。
2. 全員確定後、合成ほら貝の合図と「全員の命令が確定しました」を確認します。全員の命令線・待機・装備命令が一斉公開され、軍は元位置に残ります。
3. ゲストには「ホストが裁定開始するのを待っています」が表示されます。ホストが「▶ 裁定開始」を押すと、独立移動を区ごとに短く再生し、関連する支援・衝突は同じ局面で再生します。
4. 通常終了・早送り・スキップで最終結果が変わらないことを確認します。裁定は同時処理済みであり、演出の先後が勝敗を変えることはありません。
5. 次の移動フェイズで命令を入力し、「← 前ターン」を押します。履歴ラベル・軍配置・領土・補給拠点・公開イベントを確認します。履歴の地図をクリック・右クリックしても命令は変わらず、確定もできません。
6. 「このターンの命令を見る」で過去の公開命令線を表示し、「現在に戻る」で入力中の命令がそのまま戻ることを確認します。春と秋の2回裁定後は前後に1ターンずつ移動できます。
7. 再読み込み・再接続後にも履歴を閲覧できること、音量・設定から合図を試せること、SE OFFで鳴らないことを確認します。
8. 盤面の淡い鴨川・桂川・京都駅・地下鉄2路線は背景装飾です。川や地下鉄によって移動できる地域が増減しないことを確認します。

スクリーンショット付きの実行結果は [Phase 7G報告](PHASE7G_REPORT.md) を参照してください。下記は既存のロビー・ルール確認手順です。

## 1. 標準シナリオで遊ぶ

Phase 7Bからは正式な `data/default-scenarios/kyoto-standard.json` を内蔵しています。トップからオンライン対戦を選ぶと、標準シナリオが選択済みでルームを作成できます。地図編集やファイル選択は不要です。標準は190地域・補給拠点72か所・初期陸軍59体の設定です。参加人数による無所属区・初期軍の除外は従来の開始ルールに従います。

独自シナリオで遊ぶ場合だけ、地図エディタで確認して「設定JSONを保存」でMapConfigを用意します。MapDefinition、Preview JSON、障害物GeoJSONは代わりに使えません。エディタの未採用初期設定と正式標準は別に保持しています。

全11区が抽選候補です。参加者3人でも、11区それぞれに採用地域、初期軍、初期所有補給拠点が必要です。初期軍を置く地域は採用・侵入可能な補給拠点にします。初期補給拠点所有は「互換用 / 将来検討（homeWardId）」でその地域の元行政区を指定します。未設定・他区指定の補給拠点は中立開始です。3人の勝利目標は補給拠点23か所なので、シナリオ全体に23以上の補給拠点が必要です。配置やバランスは人が決めます。

`tests/fixtures/phase4b-kyoto-map-config.json` は自動検証専用の配置です。人の試遊用の推奨地図・バランス案ではありません。本番初期設定へ適用していません。

## 2. 起動

エクスプローラーでリポジトリ直下の **START_ONLINE.cmd** をダブルクリックします。表示された **ONLINE GAME URL** をブラウザで開きます。5173が使用中なら5174などになります。起動画面を開いたままにしてください。

PowerShellなら次です。

```powershell
Set-Location "C:\Users\zikke\Documents\kyoto-diplomacy"
npm.cmd run dev:online
```

HTMLとサーバーhealthの両方を確認して起動成功を表示します。停止は起動した画面でCtrl+C、Y/Nが出ればYとEnterです。サーバー停止で部屋・ゲーム・ログを失うため、先にログを保存します。

Phase 7Bへ更新した後は、このプロジェクトの起動画面から一度停止して起動し直します。ブラウザも再読み込みしてください。他のプロジェクトのサーバーを停止する必要はありません。

## 3. Hostがルームを作る

トップの「オンライン対戦」へ進み、ニックネームと任意の希望区を入力して「ルームを作成」を押します。標準シナリオが選択済みです。部屋コードは6文字です。ロビー上部の「コードをコピー」「招待リンクをコピー」を利用できます。開発ツールからのオンライン作成だけは、従来のエディタ設定による検証導線です。

## 4. シナリオを確認・切り替える

標準で遊ぶ場合は選択済み表示、採用数、補給拠点・初期軍総数と検証結果を確認します。ファイルを選ばずそのまま開始できます。独自設定はホストの **「カスタムJSONを読み込む」** から選びます。サーバーがDataset 00670等の正本geometryで検証・compileし、「カスタムJSON読込済み」を表示します。「標準シナリオ」を押すと正式設定へ戻せます。識別情報にハッシュがあります。失敗時は前のシナリオを保持し、開始後は変更できません。

## 5. 3～11人を招待

参加者は招待リンクを開き、入力済みコードを確認し、別nickname→「ルームへ参加」です。通常URLからコードを入力して参加することもできます。LOCALリンクは同じPCだけで利用できます。同じPCでは新しいタブを普通に3枚開きます。タブの複製は復帰情報を共有する場合があるため避けます。別PCは同じ信頼できるLANに接続し、README第16節のWEB_HOST指定を使います。希望は保証されず、残りの区は抽選です。

## 6. Error / Warningを確認

開始ボタンの近くに件数と「詳細を見る」があります。

- **Error:** 開始不可。初期軍の補給拠点以外の地域配置、11区の設定不足、不正隣接、補給拠点総数不足など。地図エディタで修正し、設定JSONを保存してHostが読み込み直します。
- **Warning:** 開始可能。区ごとの数の差、低い隣接数、複数の連結成分、原本MultiPolygon・御苑分断、国境に接する補給拠点/軍の個数など。意図した地図か人が確認します。

システムはバランスの良し悪しを採点せず、警告を自動補正しません。

## 7. 開始・プレイ

全員接続中の3～11人になり、Errorが0ならHostが「オンラインゲーム開始」を押します。試遊の既定は **5年**。開始前に変更可能で、開始時に固定します。中央設定は`data/config/game-settings.json`です。イベント重みは今回変更していません。

開始直後は地図を大きく表示し、左右トレイは閉じています。「イベント・結果」で公開イベント・前回の行軍結果、「参加者・装備」で参加者・選択地域・自分の装備や命令を確認します。トレイの外側の地図は開いたまま操作できます。

上部の「あなた: 区名」と色を確認します。自軍のピンには明るい縁取りがあります。自軍を左クリックすると移動可能な地域を青い輪郭で表示し、その地域を右クリックするとMoveを登録します。**矢印とcommand dockの「移動 → 地域名」が更新されたことを確認してください。** マップ上の装備マーカー上の右クリックにも対応しています。右ボタンを押したままの手振れは地図移動になりません。地図のドラッグは左ボタンです。タッチ操作では下部の「移動」から左クリックで移動先を選びます。移動候補にマウスを重ねると、点線で「次の一歩の参考（現在の通行条件基準）」を表示します。翌季節に移動できる保証ではありません。

支援は、支援する自軍→「支援」→対象の軍→「この軍の現在地を守る」または「この軍の移動を支援する」の順です。移動支援では合法な移動先を選びます。対象が自軍でMove入力済みなら、その移動先の推薦ボタンも使えます。他軍の秘密命令は表示しません。Escapeまたは「キャンセル」で選び直せます。支援・自転車・バリケードの操作中は右クリック移動を登録しません。

「命令書を確定」で提出します。未入力軍はHoldです。全員確定でサーバーが同時裁定し、短い確定表示に続いて約3.4秒の演出を表示します。成功移動は移動先へ進み、失敗移動は途中から戻ります。「スキップ」は確定結果へ進みます。**演出が終われば、前回の結果を開いたまま次の命令・撤退・冬調整を入力できます。**「結果を閉じる」は表示を畳むだけで、進行条件ではありません。「前回の行軍結果」から再表示できます。撤退が必要な場合は独立した案内と地図の「撤退」表示を確認してください。OSで動きを減らす設定の場合、移動量を抑えて結果を表示します。再接続時は確定済み盤面へ復帰します。開発者用の従来の詳細画面では演出を挟まず結果を表示します。

最後の確定前なら解除できます。撤退中は交渉禁止で、本人だけが撤退先を選びます。冬は必要なBuild / 手動Disbandを確定します。公開イベントのカードには地域名・区名・効果があり、マウスを重ねると該当地点を強調します。「地図で見る」で移動・ズーム・短い点滅を行います。道路工事などは辺の両端を表示します。装備・4種類の公開イベントはREADME第17節を参照してください。

終了条件は優先順に、春秋補給拠点更新後の即勝利条件達成、冬清算後の新規脱落、規定年数の冬終了です。即勝利には人数別の補給拠点目標に加え、「開始時に別の参加勢力が所有していた補給拠点を現在2個以上所有」が必要です。同じ相手の2個でも構いません。初期中立・無所属区・自分の初期補給拠点は数えません。HUDで両方の進捗を確認できます。脱落は補給拠点ゼロまたは現在支配する補給拠点以外の地域地域ゼロ。即勝利条件を満たす勢力が複数なら、その中の最多補給拠点が勝利します。冬の年数・脱落終了では敵の初期補給拠点条件を使わず、最多補給拠点が勝利し、最高数の同数は同率勝者です。順位は補給拠点数だけで決め、12、12、10なら1、1、3位です。

切断・再読み込みは同じタブなら本人として復帰します。未確定の切断者を強制処理する機能はありません。終了後も盤面と直前の公開結果を閲覧できます。

終了見出しは、自分が単独勝者なら「勝利」、同率勝者なら「共同勝利」、それ以外なら「第N位」です。担当区がないローカル試行は「対局終了」と表示します。順位・統計は全員共通です。

## 8. ログを保存

Hostは進行中の **「試遊ログをダウンロード」** を利用できます。対局終了後は全参加者が同じボタンで **match-log.json** を保存できます。既定の保存先はWindowsのダウンロードフォルダーです。

シナリオハッシュ、人数、割当、無所属区、seed、開始時設定、最終結果、時系列、補給拠点/支配地域/軍/装備数、公開イベント、取得・設置・期限、確定時間、裁定済み命令を記録します。現在の下書きや未解決命令、予約、復帰token、socket IDは含みません。nicknameと解決済み行動を含む試遊資料です。

命令フェイズの平均秒数は、入力開始から裁定までの所要時間です。実際のVC会話時間を測定したものではありません。終了画面の試遊サマリーでも確認できます。

Phase 5Bでは、支援Hold/Moveの集計、各勢力の敵の初期補給拠点・初期中立補給拠点の現在所有数、裁定スキップ数も記録します。マウス座標や下書き変更履歴は記録しません。

## 9. 試遊後にChatGPTへ送る資料

- **使用したMapConfig JSON** と **match-log.json**。同じファイル名の別試遊と混ぜないよう、コピー先のフォルダーを日付・人数で分けます。
- ロビーのError / Warning詳細、地図全体、対局終了順位・試遊サマリーのスクリーンショット。
- 人数、所要時間、使用した規定年数、初期軍数、Discord等の交渉方法。
- 詰まった操作・理解しにくい命令、国境や補給拠点の取り合い、補給拠点以外の地域ゼロ脱落の発生時期、イベントや装備が役立った場面。
- 不具合なら発生直前の操作、年・季節・フェイズ、起動PowerShellのエラー文。復帰tokenやsessionStorageの内容は送らないでください。

終了結果とログの客観値から、人が次の配置・ルール・重みの調整を決めます。今回はPhase 7Bで停止します。

## 10. BGM・効果音を用意する

音源を使う場合は、自分で用意したファイルを次の場所へ置きます。BGMは未配置、効果音は7種類の仮WAVを同梱しています。

```text
apps/web/public/audio/bgm/domestic.mp3
apps/web/public/audio/bgm/adjudication.mp3
apps/web/public/audio/sfx/march.wav
```

domesticは通常の命令・撤退・冬、adjudicationは裁定演出中に再生します。演出終了・スキップでdomesticへ戻り、前回の結果が開いていても同じ再生位置から続けます。季節変更だけでは曲を頭から再生しません。marchは移動演出中に一つだけ鳴り、移動終了・スキップで止まります。

「設定」または「音量・設定」でBGMと効果音を別々にON/OFF・音量調整できます。設定はそのブラウザに保存します。音源がない場合やブラウザが自動再生を拒否した場合も、ゲームを続けられます。詳細はREADME第20節です。

`apps/web/public/audio/sfx/` のselect / order-confirm / march / support-success / sc-capture / standoff / victoryのWAVは配置済みです。「音量・設定」→「効果音を試す」で聞けます。差し替え手順と長さの目安は同フォルダーのREADMEにあります。未配置は無音で、選択・命令・補給拠点・裁定結果を画面から確認できます。

## 11. Phase 6Aの試遊確認

- 自軍を実マウスで左クリック→合法地域を右クリック→Move・矢印・command dockへ反映すること。左右トレイを閉じた状態と開いた状態、Army・補給拠点・マップ上の装備マーカー上でも確認します。

## 12. Phase 5Cからの回帰確認

- 裁定演出を最後まで見た後、結果を閉じずに次の軍を選び、命令を登録できること。

- 「結果を閉じる」→「前回の行軍結果」で表示だけが変わり、提出状況・フェイズが変わらないこと。
- 「命令を変更」で矢印と移動先の強調が消え、装備予約が解除されること。
- 1280×720で命令ドック・確定ボタン・撤退入力を利用できること。地図が狭い場合は結果を畳むか左右のパネルを畳めます。
- 自分の終了見出し、順位、終了理由、ログ保存を確認すること。
- OSの動きを減らす設定と、音源未配置・効果音OFFでも同じ操作ができること。

## 15. 公開Web版（Phase 7A）

公開用実装の検証と実際のRender反映を区別します。既存の公開先は https://kyoto-diplomacy-web.onrender.com/ です。今回のPhase 7B変更はまだ反映していません。[DEPLOY_RENDER.md](DEPLOY_RENDER.md)に従い、GitHubへpushした後、BackendとFrontendの両方でManual Deployを実行してください。auto deployがOFFならpushだけでは更新されません。

公開Frontendを開き「公開サーバー」を確認します。Backendの休止中は起動待ちを表示し、約90秒後も未接続なら再試行できます。接続後は標準シナリオのまま、3端末で招待参加・区割当・自軍左クリック→合法地域右クリック→Move/矢印/dock・Support・確定・裁定・同じタブの再読込を確認します。カスタムJSONへ切り替える場合だけファイルを読み込みます。SE/BGMの音量・ON/OFF、7 WAVの読込も確認します。別回線の友達にも公開招待URLで参加してもらいます。

**Backend再起動・再deploy・休止でRoomは失われる可能性があります。** 保存参加情報は進行状態のバックアップではありません。失われたRoomは参加情報を消して新しく作ります。数か月後に新規ゲームを始めることを優先し、進行途中の永続保存は実装していません。対局中のManual Deployは避けます。Service Auto-Deploy OFFとBlueprint Auto Sync Noの両方を確認してください。

追加ローカル検証は `npm.cmd run test:production`。ローカルHTTPS/WSS fixtureの成功は実Renderの公開成功を意味しません。実Free cold start・インターネット別回線・本番TLSは公開後に確認し、公開URLと確認日時を試遊ログに記録してください。[PHASE7A_REPORT.md](PHASE7A_REPORT.md)へ検証範囲を記載しています。
