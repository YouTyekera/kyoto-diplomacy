従来はトップに開発用地図画面があり、Editor / Game Preview / Rules Sandbox / Online を同じ操作体系で切り替えていた。今回、トップを「オンライン対戦」「ローカルで試す」「設定」に整理し、Developer tools を別セクションへ移した。

| プレイヤーの入口 | `App.tsx` の地図ツールとモード選択 | `App.tsx` の Main Menu、設定、ローカル試遊、`OnlineGame.tsx` の作成・参加 |

これはフロントエンド内の画面切替であり、別のルーティングライブラリは導入していない。`/?room=コード` はオンライン参加、`/?tool=editor` は開発用地図画面へ直接入る。Developer tools 経由のオンライン画面では従来の詳細・命令フォームを確認できる。

ローカル試遊は従来どおり全勢力を一人で操作する検証用の年間進行である。オンラインと同じ権限付き一勢力対戦へルールを変更していない。トップへ戻って再びローカル試遊へ入っても、同じデータを使用している間は命令・年間進行・ログを保持する。

## 2. ロビーのルームコード

最初のviewportに RoomCard を表示し、大きなルームコードと「コードをコピー」「招待リンクをコピー」を配置した。カードにはHost、参加人数、接続範囲、規定年数、勝利目標、実際に採用したシナリオ名・設定ファイル名・短縮ハッシュ、採用地域数・SC数・初期軍数を表示する。

読み込んだ設定ファイル名は公開ルーム情報へ追加するが、シナリオのハッシュ計算やゲーム状態には含めない。Hostの規定年数入力はロビーの表示情報として参加者へ同期する。開始時の規定年数指定とサーバーの検証・開始処理は従来と同じである。Host以外や開始後からのロビー年数更新は拒否する。

ロビーの開始前検証は残し、通常画面にはプレイヤーが判断できる要約を出す。検証オブジェクトや全文ハッシュは開発用詳細へ置いた。

## 3. 招待の導線と接続範囲

招待リンクは現在のoriginに `/?room=ABC123` を付けて作成する。受信側ではコードを検証・大文字化して参加フォームへ入力し、名前欄へフォーカスする。

`localhost`、`.localhost`、127系、IPv6 loopback は `LOCAL / このPCのみ`。プライベートIPv4とIPv6 ULAはLAN、それ以外は一般的なNETWORK表示とした。HTTPSだけを理由にPUBLICとは表示しない。LOCALの招待リンクをコピーした場合は、同じPCからのみ利用できる旨を表示する。

Clipboard APIが使えないHTTPのLAN環境では、ブラウザのコピー処理へフォールバックする。コピー自体が拒否された場合はコードまたは招待URLを手動コピーできる表示にする。物理LANへの接続・ファイアウォール設定は今回の実機検証範囲外。

## 4. 対戦HUD

TopBarに年・季節・フェーズ、担当区、自分のSC数と勝利目標、軍数、確定状況、ルームコードchip、接続範囲、音量設定を表示する。実際のシナリオ名と規定年数も表示する。

中央は既存の地図。左に公開イベント・地面の装備・勢力別装備数・最近の裁定、右に参加者の提出状況とSC数、自分の装備と予約、無所属区、選択地域、自分の命令を置いた。左右HUDは個別に折りたためる。最近の裁定は通常画面では初期状態で折りたたむ。

通常画面ではraw region ID、ward番号、装備instance ID、全文ハッシュ、debug reason codeを表示せず、地域名・区名・日本語の命令説明を使用する。装備は種類と番号で選択できる。開発用画面には詳細を残した。

Game Over の結果表と試遊ログのダウンロードを保持し、通常画面からも利用できる。

## 5. 命令入力UX

自軍の軍を地図で選ぶとBottom ActionBarを表示する。待機はその場で指定、移動は合法な行先を地図上で選択する。支援は「待機を支援」「移動を支援」を選び、対象軍、必要な場合は移動先を順に選ぶ。他勢力の軍への合法な支援も可能。

自転車・バリケードは所持時に表示する。自転車は合法な経由地域と行先、バリケードは封鎖する辺の相手地域を選ぶ。同種装備が複数ある場合は使用する装備を選べる。キャンセル・変更、確定解除後の再編集に対応する。

オンラインの選択候補はサーバーが返した `legalOrders` から取り出し、確定する命令オブジェクトもそのリストの要素をそのまま使用する。ローカルは既存の共通合法命令生成を使用する。UI独自の移動・装備ルールは追加していない。

地図上には現段階で選べる合法対象を細いアクセント線で表示する。軍ピン・円形SC・hover地域名・控えめな選択線を維持する。通常画面に長い移動先selectを出さない。

提出フッターに入力済み軍数 / 全軍数、未入力軍がHoldになる説明、命令確定ボタンを配置した。秘密撤退と冬の増減員は既存の専用入力を維持する。自分の下書きと装備予約は従来どおりprivate情報であり、他の参加者へは公開しない。

## 6. 文字とデザイントークン

`style.css` に背景、surface、border、本文・補助文字、accent、danger、角丸、影、余白、文字サイズをCSS変数としてまとめた。日本語を含むsystem font stackを使用し、見出し・本文・補助テキストの階層を整理した。

UIの外枠・ボタン・HUDは中立色とし、既存の勢力色は保持する。太い黒outlineや新たな過剰なアニメーションは追加していない。開発用地図の既存スタイルも残している。

## 7. BGMの構成

`main.tsx` で全画面を一つの `AudioProvider` で包む。`bgm-manifest.ts` がtitle / lobby / game / resultのスロットを持ち、`audio-manager.ts` が音源・再生・フェード・音量を管理する。

| 画面・状態 | context |
| --- | --- |
| Main Menu・設定・開発用トップ | title |
| オンライン作成・参加・ロビー、ローカル開始準備 | lobby |
| 春・秋の命令、秘密撤退、冬を含む進行中の対戦 | game |
| Game Over | result |

年・季節・命令フェーズの遷移ではgame contextを変更せず、曲を再生成・再生し直さない。同じ音源を指定したcontext間でも既存の再生を保持する。曲が変わる場合は約0.9秒でcrossfadeし、無音スロットへの切替もfade outする。

最初の信頼されたpointer / keyboard操作で再生をunlockする。autoplay拒否や音源読込失敗はゲームを停止せず、音楽ボタンから再試行できる。再生失敗のエラーモーダルは出さない。BGM ON/OFFと音量0〜100はlocalStorageへ保存し、再読込時に復元する。音量変更だけでは曲を再生成しない。

## 8. 音源ファイルの配置

音源は未配置であり、初期状態では全画面無音。著作権素材、ダミー音源、ユーザーの他フォルダの音声を追加・転用していない。

ユーザーが用意した音源を `apps/web/public/audio/bgm/` へ置き、`apps/web/src/audio/bgm-manifest.ts` の `src` に `/audio/bgm/ファイル名.mp3` 等を指定する。MP3などブラウザ向けの圧縮音声を推奨する。詳しい例と設定方法はREADME第20節、および同フォルダのREADMEに記載した。実際のデコード・音質は配置した音源と使用ブラウザで確認が必要。

Viteのpublic配信先を `apps/web/public/` に整理し、従来の `data/generated/` は専用pluginで開発配信・buildへのasset出力を行う。`regions.json` 等の既存URL、NOTICE、ライセンス出力を保持する。build済みpreviewからの地図読込もブラウザテストで確認した。

1920×1080と1280×720で、中央地図が画面幅の半分を超え、提出ボタンがviewport内にあり、横方向にはみ出さないことを確認した。1280幅では左右HUDを狭くし、必要なら折りたたんで地図を広げられる。

390×844でもHUDを折りたたんだ状態で横方向にはみ出さず、提出フッターが表示されることを確認した。スマートフォンは基本fallbackであり、全画面の完成したモバイル操作設計を保証するものではない。ブラウザ固有のナビゲーションボタンに依存せず、画面内でトップ・設定へ移動できる。
