## 1. startup false negativeの原因と修正

旧wrapperはstdout/stderrの文字列に一致した内部フラグを起動成功の条件とし、30秒の起動タイマーで失敗終了していました。実HTTPが正常でも文字列検知が揃わないと停止する構造でした。ユーザー実機の元ログは保存されていないため、具体的にどの文字列・装飾が検知を外したかは特定していません。

`scripts/http-readiness.mjs`へHTTP確認を分離しました。選択Web URLが2xxのHTMLで、バックエンド`/health`が200なら成功とします。200ms間隔・約15秒の待機です。ログの内部フラグに依存しません。成功後の起動タイマーはありません。失敗時は選択URL/ポート、子プロセスの実行/終了・PID・exitCode・signal、最後の両HTTPエラー、timeoutを日本語で返し、今回起動した子だけを停止します。

イベント作業の前に7件のHTTP検証と従来の起動12件を通し、既存5173を残したまま`npm.cmd run dev:online`でWeb5174 / Server3001のHTTP 200と30秒超の継続を確認しました。最終コードでは`cmd /c START_ONLINE.cmd`でも同じURL・成功表示・数分の継続を確認し、Ctrl+Cで止めました。Windowsの中断時にY/Nやpauseが残る場合はY＋Enterで閉じられ、正常起動を失敗とするメッセージは出ません。既存の5173サーバーは停止していません。

## 2. イベントarchitecture

shared/eventsへ型と厳格Zod schema、game-core/eventsへ生成・期限・pickup・有効隣接、equipment-ordersへ装備命令を追加しました。GameSessionState.eventsが状態を所有し、静的地図・Preview JSONから分離しています。

第1年春、次の秋、次年春Ordersへ入る直前に生成します。冬には生成しません。通常裁定へ有効隣接のMapDefinitionを渡し、Move / Support / Retreatで同じグラフを使います。裁定基盤を種類ごとに複製していません。

## 3. 装備所有と予約

装備は勢力inventoryのunique instanceです。carrier unitやtransferは作っていません。使用時だけequipmentIdを軍と命令へreserveし、重複予約と各勢力各種類2軍以上の利用を拒否します。本人の命令編集は全体検証後に保存し、不正編集で古い下書き・予約を壊しません。

全撤退後、最終占有軍のownerが地面装備を取得します。MoveでもRetreatでも取得可能で、controllerとは別です。利用軍が生き残れば予約解除、最終的に破壊されれば予約装備だけを失います。未使用装備は他軍の破壊で失いません。空地の装備は無期限に残ります。

## 4. 自転車

BicycleMoveの第1区間を通常Moveと同時裁定し、その自転車軍への支援を不成立にします。成功軍だけが第2区間を同時裁定します。他軍は第2行動なし、支援なしです。入力順で勝者を選びません。曲がる経路を許可し、両区間を有効隣接で検証します。

第1区間失敗ならA、第2区間失敗ならB、両方成功ならCへ移ります。各成功到着地域の支配を反映し、出発地域の支配を維持します。equipmentResultsへ両区間の成否と理由を返します。自転車は使用だけでは消費せず、利用軍が撤退で破壊された場合だけ消えます。

## 5. バリケード

DeployBarricadeはHold相当で防御し、Support Holdを受けられます。排除されなければ成功・装備消費・pending辺保存です。今季の移動には影響せず、次の移動Ordersからactiveになります。各Orders＋関連Retreatを4回封鎖し、撤退清算で4→3→2→1→削除。冬は減らしません。

baseの恒久辺だけを選び、バスだけの辺・既設辺・次季節にも残る封鎖と合わせて連結成分を増やす辺を拒否します。既存の採用範囲が複数成分でも自動接続せず、追加の分断を防ぎます。

ユーザーの追加決定に従い、地面またはどこかのinventoryにバリケード装備があれば新しくspawnしません。世界全体で未消費装備1個となり、複数勢力の同時設置競合を生成しません。消費後のactive封鎖は持続効果として次の安全判定へ含めます。

## 6. 道路工事

baseの辺から、active封鎖と合わせても分断しない候補を選びます。controllerが異なる境界を優先し、候補がなければ安全な全候補へfallbackします。今季のMove / Support / Retreat / 自転車両区間から辺を除き、全撤退後に解除します。

## 7. 臨時バス

baseの最短距離2または3の非隣接ペアを候補とし、controllerが異なるか中立endpointを含むペアを優先します。今季のMove / Support / Retreat / 自転車で接続を利用でき、全撤退後に解除します。バス辺へバリケードは設置できません。

## 8. RNGと設定

オンラインGameSessionのサーバー生成crypto seedを使い、seed・年・季節・保存counterから決定的な乱数を派生します。イベント処理にMath.randomはありません。候補順を固定し、種類抽選と場所抽選ごとにcounterを進めます。

重みをdata/config/event-settings.jsonに全種1で保存しました。3～5人1件、6～8人2件、9～11人3件です。同じ種類を重複選択せず、候補なしの種類を除外し、生成可能数だけで続行します。種類集合は毎回減るため無限rerollはありません。開始時の設定をstateへ保存します。

## 9. オンライン秘密性とready

公開viewはイベント・地面装備・active辺/期間・勢力別所持数を明示列挙します。instances、reservations、pending辺を内部状態のまま公開しません。本人viewだけが本人のinstances・予約・経路/設置対象・合法候補を持ちます。再接続で本人の入力と予約を復元します。

自動Holdは命令がない軍だけに補完し、装備命令を上書きしません。全員確定の一回裁定、phaseKey、冬・撤退の秘密入力は維持しました。裁定後だけequipmentResultsを公開し、装備IDを含めず両区間または設置の説明を返します。

## 10. ローカル検証

年間進行でも同じ生成・隣接・予約・裁定・pickup・期限を使います。イベントseed入力と、通常ルール比較用のイベントON/OFFを追加し、初期ONです。1～2勢力のローカル検証は1件とします。オンラインにはOFF操作を追加していません。

開始・初期状態へのresetで同じseedと盤面を再現できます。年間状態は従来どおりメモリ内だけで、静的設定・Previewを変更しません。

## 11. UI

共有EventsPanelへ今季イベント、地面装備、種類別所持数、封鎖残数を表示しました。MapCanvasには独自SVGの装備記号、工事短線、バス破線、封鎖短線/残数を追加しました。装備マーカーでも地名hoverを使えます。

装備入力は所持と予約、合法経由/終点、安全な恒久辺を満たす選択肢だけを返します。自転車・設置の説明と制約を入力欄へ表示します。本人の装備詳細には使用可能/今季予約と利用軍を明記し、他人には所持数だけを表示します。本人の経路だけを描画し、従来の支配色・ピン・SC所有ring・細い選択・地名tooltipを維持しています。

オンラインE2Eで開始配信の遅延が見つかり、候補ごとの全227ポリゴン再parseを廃止しました。検証済み地図の隣接からGUI候補を作り、提出時に命令書全体を厳格に検証します。自転車第2段階が不要な場合は重複した裁定呼出しも省略します。
